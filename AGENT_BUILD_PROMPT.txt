You are integrating @convinced/widget-sdk@0.1.4 into a customer-owned website.

GOAL
Build one headless Convinced agent that works on this website's UI and capabilities. Keep one Convinced session and one Luna conversation across typed input, spoken input, knowledge, Markdown/media, page tools, identity, and handoff. The host application owns all layout and visual behavior.

ARCHITECTURE
- `gpt-6-luna` is the canonical reasoning runtime. Its message is the visible answer.
- `gpt-live-1` is optional full-duplex speech input/output. It delegates recognized speech to the same Luna chat and speaks the verified Luna result naturally.
- Typed input always calls `client.sendMessage()`, including while voice is active.
- `live.end()` turns voice off without ending chat. `client.endSession()` closes the whole experience.
- Chat-only flows must not create a Live session.
- Create one `ConvincedLiveController` with `client.createLiveController()` and reuse it.
- Never expose OpenAI keys, server secrets, management credentials, or provider configuration in browser code.

BOOTSTRAP

```ts
import {
  ClientToolRegistry,
  ConvincedClient,
  publishRegistryToWebMcp,
} from '@convinced/widget-sdk'

const tools = new ClientToolRegistry()
const client = new ConvincedClient({
  orgSlug: 'CUSTOMER_SLUG',
  agentId: 'CONVINCED_AGENT_DEPLOYMENT_ID',
  tools,
  authorizeToolCall,
})
await client.initialize()
```

`agentId` is a public Convinced AgentDeployment ID. The Convinced backend verifies that it belongs to the organization. It is not a provider ID.

CUSTOM UI
Subscribe to `client.on('message', ...)`, `client.on('message_delta', ...)`, `client.on('content', ...)`, `client.on('activity', ...)`, and tool events as needed. Render the Luna assistant message once. Do not add Live output transcripts as a second visible answer.

The SDK is headless. Choose the website's own controls, motion, responsive behavior, focus management, Markdown rendering, slide placement, video placement, form flow, and route behavior. Slides should stay in the intended experience unless the product explicitly asks to navigate.

SPEECH

```ts
const live = client.createLiveController()
await live.start({ context: currentPageContext(), startMuted: false })
live.setMuted(true)
live.setMuted(false)
live.sendContextualUpdate(currentPageContext(), 'page-state')
await live.end()
```

Use normal click-to-enable/disable or mute controls. Do not require hold-to-talk. Handle permission denial, connection failure, reconnect, interruption, and teardown. Do not create a second Live controller on remount.

TOOLS
Create one `ClientToolRegistry`. Register only capabilities the current page can execute and verify. Keep all schemas object-shaped and bounded. Use stable `host_` or `client_` names. Each tool declares:
- `version: 1`
- `name`, `description`, and `inputSchema`
- `locality: 'host'`
- `effect: 'read' | 'navigate' | 'mutate'`
- `consent: 'none' | 'session' | 'per_call'`
- a bounded timeout
- a handler that returns the real outcome after the action completes

Do not report a slide as shown until the renderer actually selected/rendered it. Do not report a form as submitted until the application accepted it. Never invent tool success.

The backend sends browser tools to Luna. When Luna requests one, the backend signs the exact call and pauses. The SDK verifies it against the registry, gets host authorization, executes it once, and returns the observation. The backend verifies organization/session/turn/call binding before resuming Luna. Spoken input follows the same path because it delegates to `client.sendMessage()`.

WEBMCP
Publish the same registry rather than building one SDK method for every page:

```ts
const webMcpPublisher = client.publishToolsToWebMcp()

await webMcpPublisher?.ready
// On route teardown: webMcpPublisher?.dispose()
```

Feature-detect WebMCP. Dispose registrations on route teardown and recreate route-specific tools after navigation. Use `createWebMcpBridge()` only to consume same-origin tools registered by another component. The direct registry remains the fallback when WebMCP is unavailable.

PROMPTS
For a customer admin UI, use `ConvincedAgentAdmin`. Never expose it as a visitor tool.

```ts
const admin = new ConvincedAgentAdmin({ orgSlug, agentId, apiBase })
const current = await admin.getPrompt()
await admin.updatePrompt({
  systemPrompt,
  firstMessage,
  expectedRevision: current.revision,
})
```

The authenticated backend must require organization ADMIN access, verify deployment ownership, persist both fields in Convinced, and return a new revision. On 409, reload before retrying.

`ConvincedAgentAdmin` sends same-origin credentials. Run it on the authenticated Convinced admin origin, or use an authenticated same-origin management proxy on the customer's admin site. Do not call it from a public visitor page.

SESSION AND SECURITY
- Initialize before chat or voice.
- End the durable session once, when the whole experience closes.
- Pass exact `slidesViewed` if your UI shows slides.
- The backend owns Live session IDs; do not collect or post provider conversation IDs.
- Treat model and tool output as untrusted data.
- Require explicit host approval for `session` and `per_call` tools.
- Redact secrets and form values from page context.
- Use same-origin navigation by default and an explicit allowlist for external navigation.
- Use HTTPS and a restrictive CSP.

ACCEPTANCE
1. A chat-only visit creates no Live session.
2. Spoken input reaches the same Luna history as text.
3. Typed input while voice is active remains visible once and is spoken.
4. Voice can end while text continues.
5. A delayed/split speech transcript becomes one correct Luna turn.
6. A slide requested from text and speech uses the same handler and renders inline as designed.
7. WebMCP works when available; direct registry still works when unavailable.
8. A mutating/per-call tool cannot execute without host authorization.
9. Repeated voice enable/mount cannot create duplicate active Live sessions.
10. No OpenAI key or server secret appears in source, HTML, source maps, logs, or browser network responses.
11. Prompt and first-message edits persist for future sessions and reject stale revisions.
12. Session history in Convinced contains the canonical user/Luna turns without duplicate speech transcripts.

Run type checking, unit/integration tests, a production build, and real-browser tests for microphone permission, typed/spoken continuity, tool execution, slides, teardown, errors, responsive behavior, keyboard use, and reduced motion. Report environment-blocked checks explicitly.
